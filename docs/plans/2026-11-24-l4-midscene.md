# 为 module-test 增加 L4：Midscene Test 端到端档位

## Context

当前技能只有 L1 静态 / L2 接口 / L3 无头浏览器三档。L3 依赖临时脚本与 DOM 选择器，语义化页面（AI 生成 UI、动态布局）上维护成本高，也不沉淀可复用资产。

用户要求增加 L4：用 [Midscene Test](https://github.com/web-infra-dev/midscene/blob/main/apps/site/docs/zh/midscene-test/overview.mdx) 写 YAML 用例、执行、沉淀到业务仓库、出报告。已确认三项决策：

1. 用例沉淀位置：业务仓库 `e2e/midscene/`。
2. 报告形态：新增「十五、L4 端到端（Midscene）」一节，其余十四节不变。
3. 运行工程：全局 runner `~/.codebuddy/skill-data/module-test/l4-runner/`，不往业务仓库装 node_modules。

已核对 Midscene 文档事实：配置为 `midscene.config.ts`（`defineTestProject` + `createMidsceneNodes(PlaywrightAgent)`）；CLI 支持 `--config / --project / --reporter verbose / --result-dir`；结果在 `test-results/<runId>/`（`result.md`、`summary.json`）；报告默认单文件 HTML（`output.reportFormat: 'single-html'`）；退出码 0/1；`setCookies` 只能用 `cookiesEnv / profile / storageStatePath` 引用，禁止 YAML 明文 Cookie；每个 Project 支持 `files.include/exclude`、`tags.include/exclude`、`retry`；步骤无跨步隐式状态；`${{ENV}}` 会写入运行结果，因此密码/密钥不得通过变量注入到步骤。

## 设计要点

### L4 定位

- L4 = Midscene Test AI 驱动 E2E：真实浏览器 + 自然语言步骤 + AI 断言，可沉淀 YAML。
- AI 断言一律按 M3；数值、金额、条数、权限、占比类结论必须另有 M1/M2 独立核验（接口/SQL），否则该条结论上限「有条件通过」。
- 只支持官方 Web Node（`aiAct/aiAssert/aiWaitFor/wait/gotoUrl/setCookies/clearCookies/setViewportSize`），不加载业务仓库自定义 Node（v1 限制，文档写明）。
- 默认 `retry: 0`；AI 抖动导致失败先定性，`-RerunFlaky` 重跑须保留两轮结果，不许静默重试。

### 套件契约（强制，降低选择复杂度）

- `e2e/midscene/suite.json` 为唯一套件清单。
- **一个 YAML 文件只放一条用例**，`file` 与 `name` 一一对应；文件名建议 `cases/<模块>/<caseId>.yaml`。
- 选择粒度：
  - `-Case L4-XXX-001`：只暂存该用例文件。
  - `-Tag smoke`：按 suite 条目 tags 选文件。
  - 不传：跑 suite 全部条目。
- 用例编号 `L4-<模块码>-NNN`；`criterion` 默认 M3，可用 `crossVerifiedBy` 记录 M1/M2 来源。

### 全局 runner 与每轮暂存

```text
~/.codebuddy/skill-data/module-test/l4-runner/
├── package.json / pnpm-lock.yaml / node_modules/
├── .env                  # 本机密钥，绝不入仓、绝不复制到产物
├── templates/midscene.config.ts
├── node-spec.md          # `midscene-test nodes` 生成，写用例前读
└── runs/<runId>/
    ├── midscene.config.ts   # 每轮生成
    ├── cases/... fixtures/...  # 从业务仓库暂存，保留相对路径
    ├── staged-manifest.json    # 源路径 + SHA256 + suite 哈希
    ├── results/                # --result-dir
    ├── artifacts/              # MIDSCENE_RUN_DIR，报告/诊断
    └── console.log             # 已脱敏
```

执行（cwd = `runs/<runId>`，Node 向上解析到 runner 的 node_modules）：

```powershell
pnpm exec midscene-test --config midscene.config.ts --project web --reporter verbose --result-dir ./results
```

环境：`MIDSCENE_RUN_DIR=./artifacts`；模型变量与 Cookie 变量由 l4-run 从 `-Secrets` / runner `.env` / 进程环境注入子进程，只注入、不落盘、不回显。

暂存整个 `e2e/midscene/cases/` + `fixtures/`（按选择裁剪），保证 `./fixtures/...` 相对引用不变；不用符号链接（跨盘 + PS 5.1 不可靠）。

### 凭据安全

- YAML 里只允许 `setCookies: { cookiesEnv: L4_COOKIES }` 或 `storageStatePath`；禁止 password/token/cookie 明文。
- 登录表单类流程（需要把密码打进 `aiAct`）v1 不支持：`aiAct` 输入会被记录到结果文件。改为预置 Cookie / storageState。
- l4-run 启动前把 Secret 值注册到脱敏表；console、l4-summary、HTML、report.md 中一律替换为 `***`。
- 产物目录不复制 `.env`、Cookie 文件、storageState。

### 写入边界（L4 唯一例外）

- 常规仍只写 `.codebuddy/selftest/<本轮>/`。
- 用户当轮授权后可写 `e2e/midscene/{cases,fixtures}/**`、`suite.json`、`README.md`，仅用于沉淀用例；业务源码/配置一律不动。
- l4-run 结束用 `git status --porcelain` 校验：只允许上述路径 + 已忽略产物；越界退出 4，本轮作废。

## 实施步骤（按文件）

### 1. 新增 `module-test/scripts/l4-init.ps1`（UTF-8 BOM）

参数：`-RunnerDir`（默认 `~/.codebuddy/skill-data/module-test/l4-runner`）、`-Install`、`-CheckOnly`、`-ModelVerify`、`-SkipPlaywright`。

- 检查 Node 版本（`^20.19 || ^22.12 || >=24`）、pnpm、runner 目录、`node_modules`、Chromium、模型 Key（`MIDSCENE_MODEL_API_KEY` 等）、`.env`。
- 首次写 `package.json`、`templates/midscene.config.ts`、`.env.example`；`-Install` 执行：
  - `pnpm add -D @midscene/test @midscene/web playwright`
  - `pnpm exec playwright install chromium`（`-SkipPlaywright` 跳过）
  - `pnpm exec midscene-test nodes --project web` 生成 `node-spec.md`
- `-ModelVerify` 在 runner 目录执行 `pnpm exec midscene-test model verify`（文档规定读取 cwd 的 `.env`）。
- 退出码：0 就绪 / 2 缺前置 / 1 执行错误。

### 2. 新增 `module-test/scripts/l4-run.ps1`（UTF-8 BOM）

参数：`-Round`（必填，必须位于 `.codebuddy/selftest/` 下）、`-RepoRoot`（默认当前目录）、`-Suite`（默认 `e2e/midscene/suite.json`）、`-Case`、`-Tag`、`-Secrets`、`-Authorize`、`-DryRun`、`-UpdateSuite`、`-RerunFlaky`。

流程：

1. 前置检查（runner、suite、用例文件、授权、git 仓库）。
2. 读 suite + YAML 校验 1:1 契约；计算源文件 SHA256；`-DryRun` 到此打印命令即退出 0。
3. 建 `runs/<runId>/`，暂存 cases/fixtures，生成 config（`files.include: ['cases/**/*.{yaml,yml}']`、`output.reportFormat: 'single-html'`），写 `staged-manifest.json`（suite 哈希 + 每文件哈希 + 选择条件）。
4. 注入 Secret 环境变量；执行 CLI；console 写 `console.log`（脱敏）。
5. 复制结果到本轮：`<Round>/l4/midscene/{result.md,summary.json,report.html}`；步骤截图复制到 `<Round>/shots/l4/<caseId>-stepN.png`（沿用现有 `shots/` 路径校验，避免相对路径拼接错位）。
6. 调 `l4_summary.py` 生成 `<Round>/l4/l4-summary.json`；`-UpdateSuite` 时调 `l4_suite.py upsert` 回写 `lastStatus/lastVerified`。
7. `git status` 越界检查。
8. 退出码：0 全通过 / 1 有失败 / 2 缺前置 / 3 未授权 / 4 暂存或套件非法（含 git 越界）。

### 3. 新增 `module-test/scripts/l4_suite.py`

子命令：

- `collect --repo-root . --suite e2e/midscene/suite.json [--module X] [--authorize]`：扫描 `cases/**/*.yaml`，轻量解析 `name/tags`（不引入 PyYAML），合并已有条目（保留 `firstSeen/lastStatus`），校验 1 文件 1 用例；无 `--authorize` 只打印 diff。
- `upsert --suite ... --case-id ... --status passed|failed [--date] [--authorize]`：更新单条执行结果。
- `export --suite ... [--out file]`：输出十五节可粘贴的 Markdown 表，不写仓库。

suite schema（同时作为 `assets/midscene-suite.schema.json`）：

```json
{
  "schemaVersion": 1,
  "project": "web",
  "module": "<模块名>",
  "cases": [{
    "caseId": "L4-ORD-001",
    "file": "cases/order/L4-ORD-001.yaml",
    "name": "创建订单",
    "tags": ["smoke", "order"],
    "requirementRef": "需求原文 §2.1",
    "criterion": "M3",
    "crossVerifiedBy": ["M2: SQL 订单条数"],
    "firstSeen": "2026-11-24",
    "lastVerified": "2026-11-24",
    "lastStatus": "passed"
  }]
}
```

### 4. 新增 `module-test/scripts/l4_summary.py`

- 输入：结果目录（递归找 `summary.json`、`result.md`）、suite、staged-manifest、console。
- 输出 `l4-summary.json`（schemaVersion 1）：`runId/exitCode/counts/cases[]/stagedFiles[]/redacted[]`；每条含 `caseId/name/file/status/criterion/crossVerifiedBy/steps[]/failedStep/screenshots/evidenceLevel/unmapped`。`screenshots` 用本轮相对路径 `shots/l4/<caseId>-stepN.png`。
- `summary.json` 字段可能随版本变化：实现为多形状容错（list / `cases` / `results` 嵌套），并用 `result.md` 计数兜底。
- 按 `name` + `file` 匹配 suite；选中的 suite 用例在结果中缺失（且非 skipped）→ 标记 `unmapped`，l4-run 退 4。
- 脱敏：按 Secret 值精确替换；递归抹掉 `apiKey/token/cookie/authorization` 类键值；输出中不出现 `.env` 内容。
- CLI：`--results --suite --staged --console --out --secrets-json`。

5. 干跑：在临时目录造 `e2e/midscene/suite.json` + 1 条用例，`l4-run.ps1 -Round ... -DryRun` 检查暂存树、config、命令、staged-manifest 哈希。

## 风险与回退

- `summary.json` 结构漂移：脚本容错 + 真实运行校准；无法解析时以 exit code 为准并要求人工核对 `result.md`，不得静默判通过。
- 模型抖动/成本：默认不重试；`-RerunFlaky` 显式重跑并保留两轮证据；文档给出低成本 smoke 用例。
- 认证：只支持 Cookie/storageState 引用；需要输入密码的流程明确判「未覆盖」并给四要素。
- 路径/编码：全部绝对路径 + 递归创建；PS 5.1 BOM；console UTF-8；不复制大文件，只复制报告与截图。
- 越界写：l4-run 用 git status 强制校验，越界即失败；未授权时不写 `e2e/midscene`。
