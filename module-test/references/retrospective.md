# 复盘与自我迭代

每轮自测结束都要复盘，但**不是写感想**——只记能改变下一轮行为的东西。

## 一、四个必答问题

| # | 问题 | 判断标准 |
|---|---|---|
| 1 | **漏网**：本轮发现的问题里，有没有现有检查项覆盖不到的？ | 把缺陷回套检查清单，找不到对应条目 = 漏网，必须补一条 |
| 2 | **空转**：有没有跑了但永远不适用、或查不出东西的检查项？ | 连续 ≥3 轮不适用，考虑降级/合并/删除 |
| 3 | **阻塞**：命令失效、路径变了、工具不好用？ | 下次会再卡一次，就得改 |
| 4 | **新知识**：这轮摸清了什么以前不知道的口径/结构？ | 只记会影响判定的，不记流水账 |

## 二、漏网判定（最关键）

```
本轮发现的缺陷
  → 回套 SKILL.md 的 R 规则 + 对应 reference 的检查项
    → 找得到条目、条目本身够用：不算漏网（只是没执行到，属于纪律问题）
    → 找得到条目、但条目描述太宽导致没查到：算**规则不够细**，补细则
    → 完全找不到条目：算**漏网**，必须新增检查项
```

**"纪律问题"和"规则问题"要分开记**：前者说明执行不到位（该加强自检），后者才需要改技能。

## 三、记录格式

写进技能目录的 `EVOLUTION.md`，一条一行，append-only：

```markdown
## YYYY-MM-DD  <功能名>（L3）
- 漏网：<缺陷> → 补 `<文件>` 第 X 项
- 空转：R-08 连续第 2 轮不适用（模块只读）
- 阻塞：`<browser-tool> install` 国内超时 → 已在 project-profile 记为不用
- 新知识：<口径/结构>
```

只写四类标签之一，不写"整体感觉良好"这类无信息内容。

## 四、什么时候合并进技能

| 触发条件 | 动作 |
|---|---|
| 出现**漏网** | 下一轮开测**之前**改，不等累计 |
| 同类空转 ≥3 轮 | 降级、合并或删除该检查项 |
| 阻塞 ≥2 次 | 改命令或换工具 |
| 其余 | 攒够 3 条一起改 |

**禁止边测边改**：自测执行中途不改 SKILL.md / references，避免同一轮里标准漂移。改动一律放在两轮之间。

## 五、合并纪律

1. 改哪个文件：检查项进对应 `references/*.md`；流程/契约进 `SKILL.md`
2. 每次合并升版本号：补检查项 = 次版本 +1；重构 = 主版本 +1
3. `EVOLUTION.md` 里补一条「合并记录」，写清改了哪条、为什么
4. 合并后跑一次 `scripts/check-report.ps1` 对最新报告做回归，确认没把结构改坏

## 六、反模式

| 反模式 | 后果 |
|---|---|
| 日志只写「无」 | 等于没复盘，连续几轮后技能停止进化 |
| 把主观感受当改进（「感觉太慢」） | 无法验证，下次还是原样 |
| 每轮都改 SKILL.md | 标准漂移，跨轮结果不可比 |
| 只加不减 | 规则膨胀，最终又变成 600 行的大文档 |
| 漏网了只记不改 | 同一个缺陷会在下个模块重现 |
